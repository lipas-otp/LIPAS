# A3 v0.1 — Fold Determinism Contract

**Status**: DRAFT (v0.1)
**Scope**: `lipas/calculus.py`, `lipas/testing/deterministic_fold.py`, `tests/test_fold_determinism.py`
**Related**: A1 (RFC-001 §2.5) — fold-time determinism is a precondition for the replay equivalence relation
**Not an RFC**: A3 is a code-level contract + tooling, not an RFC. It does not consume an RFC number.

## 0. Scope Correction vs. Previous Draft

A previous iteration of A3 expanded into a standalone `DeterministicFoldGuard` covering payload-level canonicalization, filesystem contracts, and belief-entry validation. That scope is **not A3**. It conflated two distinct concerns:

> Can a strategy function read the clock / environment / network?

versus payload hygiene at the tool layer. The latter is a separate (and lower-priority) RFC. A3 sticks to the narrower question, because no amount of payload canonicalization saves replay equivalence if strategies themselves are impure.

## 1. Scope

A3 defines the purity contract for **all fold strategy functions** in `lipas.calculus` and provides tooling that enforces the contract at test time.

- **In scope**: any function registered to the strategy registry, with signature `strategy(a, b, ctx, registry) -> a'`.
- **In scope**: BeliefContext access semantics during fold (read-only, fixed-snapshot per fold call).
- **Out of scope**: tool-layer payload canonicalization (path, set, float NaN, etc.) — separate RFC.
- **Out of scope**: strategy invocation at replay time — A1 already covers that.
- **Out of scope**: evolution of the strategy registration mechanism itself — that is part of A2 (schema evolution).

## 2. Why

A1 §2.5.1 requires that the post-replay claim trace be payload-equivalent to the original trace. The weakest link in that equivalence chain is the strategy function: a strategy decides post-fold row state, and post-fold row state feeds the next strategy. A single impure call amplifies monotonically along the fold chain.

Concrete failure modes — all currently permitted by the code, all of which break replay:

- A strategy calls `time.time()` to populate a row's `last_updated` field. The same claim sequence yields different rows on two folds.
- A strategy reads `os.environ["LIPAS_MODE"]` to branch. Environment changes alter the fold path.
- A strategy calls `random.random()` for tie-breaking. Direct nondeterminism.
- A strategy **writes** to BeliefContext rather than reading from it. The next strategy in the same fold call observes mutated ctx state.

These are not hypotheticals. Two such cases (`time.time()` and one `os.environ`) have already been caught by review in the alpha examples. A3 replaces "catch by review" with "catch mechanically in CI."

## 3. Strategy Purity Contract (lands at the top of `calculus.py`)

The block below is the **normative text** to be pasted into `lipas/calculus.py`'s module docstring. It is not commentary.

```python
"""
lipas.calculus — fold strategies.

NORMATIVE: Strategy purity contract
====================================

A strategy function is any callable registered to the strategy registry,
with signature::

    strategy(a, b, ctx, registry) -> a'

Strategies MUST be pure functions of their four arguments. Concretely:

  ALLOWED inputs to a strategy:
    - `a`, `b`           : the two claim/row values being merged
    - `ctx`              : the BeliefContext, treated as read-only (§3.2)
    - `registry`         : the strategy registry, treated as read-only

  FORBIDDEN inputs (non-exhaustive; the test tool enumerates the closed list):
    - time.time(), time.monotonic(), datetime.now(), datetime.utcnow()
    - random.* (any module-level state)
    - os.environ (read or write)
    - any I/O: open(), socket, subprocess, http, file reads
    - any global mutable state outside `a`, `b`, `ctx`, `registry`
    - any thread/process identity (os.getpid, threading.current_thread)

  FORBIDDEN side effects:
    - mutation of `a`, `b` in place (return a new value)
    - mutation of `ctx` (see §3.2)
    - mutation of `registry`
    - logging at WARNING or above (DEBUG/INFO is tolerated; see §3.3)

  REQUIRED:
    - Determinism: strategy(a, b, ctx, registry) called twice with equal
      arguments MUST produce equal results, in any process, on any host.
    - Totality on the declared domain: strategies SHOULD NOT raise on
      well-typed inputs; if they do, the exception type itself becomes
      part of the fold semantics and MUST be deterministic.

This contract is enforced in tests via `lipas.testing.deterministic_fold`.
It is NOT enforced in production: the cost of runtime sandboxing is not
justified, and the test gate is sufficient because strategies are a
closed set registered at import time.

Cross-ref: A1 §2.5.1 (observational equivalence at replay) depends on
this contract. Violations here surface as `ResultDrift` at replay time.
"""
```

### 3.1 Why a contract rather than runtime enforcement

Three reasons not to runtime-sandbox strategies:

1. The strategy set is closed at import time; a single CI pass per build is sufficient to lock it.
2. Runtime monkeypatching of `time` / `os.environ` would pollute tools running concurrently in the same process — tools are *allowed* to read the clock.
3. The cost/benefit is poor. Strategies are few, change rarely, and CI gating is cheap.

### 3.2 BeliefContext access pattern in strategies

The contract permits `ctx` as input under two restrictions:

- **Read-only**: strategies MUST NOT call `ctx.set(...)`, `ctx.update(...)`, or any write-side method.
- **Fixed snapshot per fold call**: within one `Store.fold(claims)` call, every strategy observes the same immutable snapshot of `ctx`. Updates to ctx are deferred until after the fold completes.

Implementation: at the fold entry point, the current `BeliefContext` is wrapped in a `ReadOnlyBeliefView` (a dataclass whose setters raise `LipasFoldContractError`). Strategies receive that view. In the alpha codebase, `BeliefContext` is only mutated via `BeliefContext.absorb`, which is never called inside fold, so the surface area of this change is near-zero.

### 3.3 Logging exception

DEBUG and INFO logging from inside strategies is permitted. Rationale:

- Logging is technically I/O, but as long as the log content is a pure function of strategy inputs, the side effect (writing to a log sink) does not violate trace equivalence on replay — replay simply writes the log entry again.
- In practice, debugging fold chains often requires INFO-level logging from inside strategies. A blanket ban makes diagnosis painful.

WARNING and above are forbidden because in production they typically trigger monitoring counters or alerts, which are real side effects with semantic weight.

## 4. Test Tooling — `lipas.testing.deterministic_fold`

New file `lipas/testing/deterministic_fold.py`:

```python
"""Test-time enforcement of the strategy purity contract (A3 §3)."""
from __future__ import annotations

import contextlib
import os
import random
import socket
import time
from typing import Iterator
from unittest.mock import patch


class StrategyContractViolation(AssertionError):
    """Raised when a strategy touches a forbidden input/side-effect.

    Carries the offending API name so that test failure messages point
    directly at the violation rather than at a deep stack frame.
    """

    def __init__(self, api: str, hint: str = ""):
        msg = f"Strategy violated A3 purity contract: touched `{api}`."
        if hint:
            msg += f" {hint}"
        super().__init__(msg)
        self.api = api


def _trip(api: str, hint: str = ""):
    def _raise(*_a, **_kw):
        raise StrategyContractViolation(api, hint)
    return _raise


# Closed list of forbidden APIs. Adding to this list is an A3 amendment.
_FORBIDDEN = {
    "time.time":           _trip("time.time"),
    "time.monotonic":      _trip("time.monotonic"),
    "time.perf_counter":   _trip("time.perf_counter"),
    "random.random":       _trip("random.random"),
    "random.randint":      _trip("random.randint"),
    "random.choice":       _trip("random.choice"),
    "socket.socket":       _trip("socket.socket", "no I/O in strategies"),
}


class _EnvProxy:
    """os.environ proxy that raises on any access during fold."""
    def __getitem__(self, key):
        raise StrategyContractViolation("os.environ", f"read of {key!r}")
    def __setitem__(self, key, value):
        raise StrategyContractViolation("os.environ", f"write of {key!r}")
    def get(self, key, default=None):
        raise StrategyContractViolation("os.environ", f"read of {key!r}")
    def __contains__(self, key):
        raise StrategyContractViolation("os.environ", f"check of {key!r}")


@contextlib.contextmanager
def deterministic_fold() -> Iterator[None]:
    """Context manager: enforce A3 strategy purity contract within block.

    Usage::

        from lipas.testing.deterministic_fold import deterministic_fold

        with deterministic_fold():
            store.fold(claims)

    Any strategy that calls a forbidden API during fold raises
    `StrategyContractViolation` immediately, with the API name in the
    message.

    Note: this wraps the *entire* fold call. Tools running inside the same
    process but outside `store.fold` are unaffected — the patches are torn
    down on exit. Do NOT nest with itself; nested entry is a no-op but the
    inner exit will tear down patches the outer relied on (deliberately
    not supported in v0.1; raises RuntimeError if attempted).
    """
    if getattr(deterministic_fold, "_active", False):
        raise RuntimeError(
            "deterministic_fold() is not re-entrant in v0.1. "
            "Wrap the outermost fold call only."
        )
    deterministic_fold._active = True

    patches = []
    try:
        for dotted, replacement in _FORBIDDEN.items():
            mod, _, attr = dotted.rpartition(".")
            patches.append(patch(f"{mod}.{attr}", replacement))
        patches.append(patch.object(os, "environ", _EnvProxy()))

        for p in patches:
            p.start()
        yield
    finally:
        for p in reversed(patches):
            try:
                p.stop()
            except RuntimeError:
                pass  # already stopped
        deterministic_fold._active = False
```

### 4.1 Design notes

- **Closed list**: `_FORBIDDEN` is enumerated explicitly; adding an API is an amendment to A3. This guards against "heuristic under-coverage" — only the genuinely error-prone members of `time` are listed, rather than patching the whole module (which would have collateral damage).
- **`os.environ` via proxy, not patch**: directly patching `os.environ` would break process-level state. The proxy serves as a sentinel inside the fold context only; on exit, `os.environ` is untouched.
- **Non-reentrant**: v0.1 raises explicitly. If nesting becomes necessary, a refcount can be added; speculative generality is not warranted.
- **`datetime.now` not patched directly**: `datetime.now` internally calls `time.time`, which is already trapped. Adding a redundant trap would only obscure error messages.
- **`open` / `subprocess` / `http` not patched**: these "should never be legal in a strategy", but patching `open` breaks logging itself (logging holds file handles). Instead, `socket.socket` is used as the I/O sentinel — any real network/HTTP path goes through socket; file I/O is caught by review. This is a deliberate trade-off, listed in §7 Open Questions.

## 5. Regression Tests

New file `tests/test_fold_determinism.py`:

```python
"""A3 §5 — regression tests for fold-time strategy purity."""
import pytest

from lipas.calculus import register_strategy, strategy_registry
from lipas.store import Store
from lipas.testing.deterministic_fold import (
    StrategyContractViolation,
    deterministic_fold,
)
# Import each example to register its strategies + run a representative trace.
from examples import (
    ex01_minimal,
    ex02_two_tools,
    ex03_supervisor_lite,
    ex04_belief_merge,
    ex05_replay_cursor,
    ex06_capability_budget,
)


# --- Test 1: examples regression -------------------------------------------

ALL_EXAMPLES = [
    ex01_minimal,
    ex02_two_tools,
    ex03_supervisor_lite,
    ex04_belief_merge,
    ex05_replay_cursor,
    ex06_capability_budget,
]


@pytest.mark.parametrize("example", ALL_EXAMPLES, ids=lambda m: m.__name__)
def test_example_folds_are_deterministic(example):
    """Every shipped example must fold cleanly under the A3 contract."""
    with deterministic_fold():
        result = example.run()  # each example exposes a top-level run()
    assert result is not None, f"{example.__name__}.run() returned None"


# --- Test 2: positive control (the tool MUST catch a real violation) -------

def test_violation_is_detected():
    """Sanity check: a deliberately-impure strategy is caught.

    This guards against the test tool silently no-op'ing — without this,
    a future refactor that breaks the patches would make Test 1 pass
    vacuously."""
    import time

    @register_strategy("a3_test_impure_strategy")
    def impure(a, b, ctx, registry):
        return a + time.time()  # forbidden

    store = Store()
    try:
        with pytest.raises(StrategyContractViolation) as excinfo:
            with deterministic_fold():
                # a minimal claim sequence that will route to `impure`
                store.fold_with_strategy("a3_test_impure_strategy", 1, 2)
        assert excinfo.value.api == "time.time"
    finally:
        # registry hygiene: unregister so other tests aren't polluted
        strategy_registry.unregister("a3_test_impure_strategy")
```

### 5.1 Why Test 2 (positive control)

Test 1 asserts "all examples must pass." But if `deterministic_fold` is one day reduced to a no-op context manager by a careless refactor, Test 1 will still pass — vacuously. Test 2 deliberately writes an impure strategy and asserts it is **caught**. This is regression protection on the tool itself.

The pattern is borrowed from database fuzzers and property-test communities: *assert that the assert works.*

## 6. Edge Cases / Non-Goals

- **Timestamps inside `logging`**: the `logging` module's formatter calls `time.time()`. If a strategy emits an INFO log, the patch fires and raises. **Resolution**: the `time.time` substitute should inspect the call stack and pass through if the immediate caller is a logging-module frame. This is implicitly promised by §3.3 but **not implemented in v0.1** — none of the current example strategies emit logs, so the issue does not surface. A `# TODO(A3.v0.2): logging frame allowlist` comment is left in the code.
- **`uuid.uuid4()`**: not in `_FORBIDDEN`. UUID generation does not appear in current calculus; if a future strategy needs an id, it should accept it via ctx rather than generating one. Recorded as a review rule in the contract text.
- **C-extension bypass**: it is technically possible to `import _time; _time.time()` and bypass the patch. **Not defended against** — A3 is a cooperative contract, not a sandbox. Adversarial bypass is out of the threat model.
- **Cross-strategy module-level dicts for communication**: §3 already forbids "any global mutable state outside `a, b, ctx, registry`." The test tool does not catch this mechanically (cannot, in general); it remains a review rule.

## 7. Open Questions for Review

1. **Whether to trap `open` / file I/O.** §4.1 argues against it because of the conflict with logging. But strategies reading config files is a likely temptation, and the cost of missing it is high. **Lean**: not in v0.1; defer to v0.2 with a narrow `pathlib.Path.open` trap and a logging allowlist.
2. **Logging frame inspection.** §6 defers it to v0.2. With the example count growing, a strategy will almost certainly want INFO logging within three weeks. **Lean**: leave the TODO comment in `_FORBIDDEN["time.time"]` so the next maintainer doesn't rediscover the trade-off from scratch.
3. **`ReadOnlyBeliefView` wrapper overhead.** Every fold call wraps the BeliefContext, which is a microscopic overhead on the hot path. **Lean**: correctness first; benchmark if it surfaces (same principle as B1's "re-fold from log" choice).
4. **Should `StrategyContractViolation` be a `LipasError` subclass?** It currently inherits from `AssertionError` because it only fires in tests. A1's error hierarchy puts all internal errors under `LipasError`. **Open**: depends on whether A3 violations are framed as production-relevant contract breaches. **Lean**: keep `AssertionError` — A3 is test-only, and folding it into the production hierarchy would falsely imply runtime relevance.
